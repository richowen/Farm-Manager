# Products Autofill Feature

## Problem
When entering products (fertilizer, spray, worming, vet treatment) in the EventForm, users must type the full product name every time. Previously-used products should be remembered and offered as suggestions.

## Affected Event Types (all use `metadata.product` key)
- `fertilizer` — "Product" field
- `spray` — "Product" field
- `worming` — "Product" field
- `vet_treatment` — "Treatment" field

## Architecture

### 1. DB Migration — `db/migrations/0013_products.sql`
Create a simple `products` table:
```sql
CREATE TABLE IF NOT EXISTS products (
  name         text PRIMARY KEY,
  last_used_at timestamptz NOT NULL DEFAULT now(),
  created_at   timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS products_last_used_idx
  ON products (last_used_at DESC);
```

### 2. Server Repository — `src/lib/server/repositories/products.ts`
New file with two functions:
- `listProducts()`: `SELECT name FROM products ORDER BY last_used_at DESC` → returns `string[]`
- `upsertProduct(name: string)`: `INSERT ... ON CONFLICT (name) DO UPDATE SET last_used_at = now()`

### 3. API Endpoint — `src/routes/api/products/+server.ts`
- `GET /api/products` → returns `{ items: string[] }`
- Protected (requires auth, like other endpoints)

### 4. Client API — `src/lib/client/api.ts`
Add `listProducts(): Promise<{ items: string[] }>` method to the `api` object.

### 5. Events Repository — `src/lib/server/repositories/events.ts`
Modify `createEvent`, `updateEvent`, and `createBatch` to call `upsertProduct()` when `metadata.product` is a non-empty string. Import `upsertProduct` from the products repository.

### 6. EventForm.svelte — `src/lib/components/EventForm.svelte`
- On `onMount`, call `api.listProducts()` and store results in a local array
- For fields where `key === 'product'`, render the input with a `list="product-suggestions"` attribute
- Add a `<datalist id="product-suggestions">` with `<option>` elements for each product
- Wrap the API call in try/catch — if it fails, the form still works without suggestions

## Edge Cases
- Empty product names are ignored
- API failure is silently handled (form works without suggestions)
- Products are trimmed before upserting
- Case-sensitive matching (user manages duplicates)
- Works for both single events and batch events
